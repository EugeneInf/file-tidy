# file-tidy

把乱糟糟的下载文件夹按扩展名整理成子文件夹。命令行跑一下，一秒变整齐。

## 它解决什么问题

下载文件夹里堆了 200 个文件：截图、PDF、安装包、压缩包、作业代码，每次找东西都要翻半天。

这个工具把它们按扩展名分进「图片 / 文档 / 压缩包 / 音视频 / 代码 / 安装包 / 其他」七个文件夹，重名自动加序号，不会覆盖。

## 怎么运行

需要 Python 3.10+，**没有第三方依赖**（只用标准库）。

```bash
# 1. 先演练：只打印计划，不动任何文件
python file_tidy.py D:\Downloads --dry-run

# 2. 看着没问题，再真的整理
python file_tidy.py D:\Downloads
```

## 目录结构

```
file-tidy/
├── README.md          <- 你现在看的这个文件，是项目的"门面"
├── file_tidy.py       <- 全部代码，一个文件够用，不用硬拆
├── requirements.txt   <- 依赖清单（这个项目没有外部依赖，所以是空的）
└── .gitignore         <- 告诉 git 哪些文件不用管（缓存、虚拟环境等）
```

## 它是怎么工作的（3 步）

1. **列文件**：`target.iterdir()` 把目标文件夹里的东西列出来，跳过子文件夹和隐藏文件。
2. **分类**：看扩展名，去 `CATEGORIES` 这张表里查它属于哪一类，查不到就归「其他」。
3. **移动**：拼出新路径，重名就加 `_1`、`_2`；`--dry-run` 时只打印不移动。

## 已知限制 / 下一步可以做

- [ ] 现在只按扩展名分类，没有按日期、按大小分
- [ ] 没有「撤销」功能（可以加一个移动日志，支持回滚）
- [ ] 不支持一次性整理多个文件夹
- [ ] 可以加配置文件，让用户自定义分类规则

> 一个小项目的价值不在于功能多，而在于**能跑、能被别人照着 README 跑起来、并且你知道下一步该加什么**。

## 我在这上面学到的东西

- `pathlib.Path` 比 `os.path` 好用：`Path("a") / "b"` 就是拼路径
- `argparse` 十分钟就能做出像样的命令行参数
- `--dry-run` 是处理"会删/会改文件"的操作时的好习惯：先演练，再执行
